# VDPコマンド終了時のレジスタ状態

## 概要

[vdp_command.v](vdp_command.v) のコマンド終了時レジスタ状態を、V9958の「6.7 コマンド終了時のレジスタの状態／表4.7」に合わせた。
STOPを含むV9958互換13コマンドと、V9968追加3コマンドを一つの表にまとめる。
追加コマンドは、LFMM/LFMCを除き、同種の互換コマンドと同じ値の残り方にした。

- LRMMはLMMMと同じく、SY、DY、NYを更新する。
- LFMMとLFMCは、1文字ずつ描いて文字列を作れるよう、DXを次の文字位置へ進め、DYとNYを保持する（同種のLMMCとは異なる）。
- LFMCのCLRには、LMMCと同じくCPU転送値が残る。

追加コマンドの用途とパラメータは [技術資料](../../../../doc/manual/V9968_MSX-VIDEO_Technical_data_Book.odt) 第8章を参照。

2026-11-22の修正で、V9958と異なっていた次の動作を直した。

| 項目 | 修正前 | 修正後 |
|---|---|---|
| 矩形コマンドのNY | 加算カウンタの値（通常完了でNY0） | 残り行数（通常完了で0、画面端で `NY0 - N`） |
| LMCMのSY | 最終行の分を進めない（`SY0 ± (N-1)`） | `SY0 ± N` |
| POINTのCLR | 保持（S#7のみ更新） | 読み出した色（S#7と同じ） |
| STOPのNY | 1を書き戻す | 中断したコマンドの残り行数。実行中でなければ保持 |
| LRMMのSY | 参照Yの固定小数点内部値 | SY0（SXと同じく保持） |
| LFMMのDX/DY/NY | DX0 + 8×NX、DY0、1 | DX0 + 8×NX、DY0、NY0（NYだけを修正） |
| LFMCのDX/DY/NY | DX0、`DY0 ± N`、NYはLMMCと同じ | DX0 ± NX、DY0、NY0（LFMMに合わせた） |
| LFMMのフォントアドレス | 他コマンドでも進む | LFMMだけが進める |

CMR Hは、内部コマンドコードを0に戻さない現在の実装のままとした（後述）。

## 表の読み方

- `-`：コマンド処理では変更しない。CPUからの書き込みとモード変更は別（後述）。
- `*`：終了座標、または読み出した色に更新する。
- `#`：NY。通常完了で0、画面端で打ち切った場合は残り行数 `NYB = NY0 - N`。
- `T`：CPU転送で最後にR#44へ書いた値が残る。
- `F+`：LFMMの内部フォントアドレスが進む。
- `(仕様外)`：表4.7と異なるが、意図して残した動作。

`SY0/DY0/NY0` は開始時の値、`N` は処理した行数を表す。
`SY* = SY0 ± N`、`DY* = DY0 ± N` は、DIY=0なら加算、DIY=1なら減算する。
LINEの `N` はY方向に進んだ量。座標とカウンタは実装のビット幅で折り返す。

## 各項目の詳細

### 1. NY：残り行数

[NYカウンタ](vdp_command.v#L976) は、矩形コマンドの開始時にNY0を読み込む。
最後の行を含め、行末ごとに1減らす。カウンタが1の行を最後の行とし（[終了判定](vdp_command.v#L1030)）、
終了時にカウンタをNYへ書き戻す。

- 指定行数を処理した場合は0になる。NY0=0の場合は1024行（256KBモードでは2048行）を処理し、0になる。
- 画面端で打ち切った場合は `NY0 - N` になる。例：HMMV、DY0=1、NY0=4、DIY=1の場合、2行描いたところで終わり、NY=2、DY=1023（256KBモードでは2047）。
- 128KBモードのDIY=0では、DYが1023から0へ折り返して描画を続ける。この場合、Y下端では打ち切らない。打ち切りは従来どおり。
- POINT/PSET/SRCH/LINEでは、NYを変更しない。
- LFMMは文字ごとにNY0を再び読み込む。最後の文字の後もNY0を読み込むため、終了時のNYはNY0のまま（Y端で打ち切った場合も同じ）。
- LFMCも、[最終行の後にNY0を読み込み直す](vdp_command.v#L1014) ため、NY0のまま。
- STOPを実行中のコマンドに対して発行した場合は、中断時点の残り行数を残す。実行中でなければNYを変更しない。

### 2. LMCM：最後の行もSYを進める

[最終転送](vdp_command.v#L1665) でも行カウンタとSYを進める。
このため、SY = `SY0 ± N`、NY = 0 になる。CLRとS#7には、最後に読み出した色が残る。

### 3. POINT：CLRにも読み出した色を残す

V9958では、S#7とR#44は同じ色レジスタである。
POINTの終了時に、[CLR](vdp_command.v#L1077) にもS#7と同じ読み出し色を入れる。
画面外から開始し、読み出しをせずに終わったPOINTは、S#7とCLRの両方を保持する。

### 4. CMR H：内部コマンドコードは0に戻さない

表4.7では、終了時にCMR Hが0になる。本実装では、内部コマンドコードを0に戻さない（仕様外）。

- [CE](vdp_command.v#L1315) は、フラッシュ完了後に必ず0になる。コマンドが再実行されることはない。
- R#46はCPUから読み戻せない。このため、内部コードが残っていても外部からは観測できない。
- Geo3Dの水平LINE最適化は、終了時に内部コードをLINEへ戻す。これを壊さないため、この動作を残した。
- CMR Lの論理演算とARGは、コマンド処理では変更しない。

### 5. LRMM

LRMMは、参照元を回転・拡大縮小して転送する。DY、NYは、LMMMと同様に終了座標と残り行数になる。
SX/SYは参照の開始点を表し、各行はSX/SYからVX/VYで計算する。
このため、SX/SYは「SYも変更する」LMMMとは異なり、終了後も設定値のまま保持する。

- 内部では参照Yを固定小数点値として進める。[終了時](vdp_command.v#L525) には、[開始時のSY](vdp_command.v#L575) へ戻す。XHR=1では内部で2倍スケールにするが、この場合も元のSYへ戻す。
- コマンド実行中にCPUがR#34/R#35を書いた場合は、その値を新しいSYとする。
- STOPで中断した場合は、コマンド種別がSTOPになるため、SYを開始値へ戻さない。中断後にLRMMを再実行する場合は、SYを再設定する。
- VX/VYとウィンドウ4座標は、CPUからの書き込みでだけ変更する。

### 6. LFMC / LFMM

LFMCは、開始時のCLRを前景色として保存する。R#44自体は、CPUから書き込むフォントパターンで上書きする。
LMMCと同様、CLRには最後に書いたパターンが残る。終了後に前景色を再利用するには、R#44を再設定する。
背景色R#12は、両コマンドとも変更しない。

LFMCは1文字（NXドット×NY行、1行＝R#44への1バイト）を描く。終了後にR#44（前景色）とR#46を書き直せば、続きの文字を同じ行に描ける。
- DXは、[最終行の後に](vdp_command.v#L650) `DX0 ± NX`（DIX=1で減算、9bitで折り返す）へ進む。画面X端で文字の途中に終わった場合は進めない。
- DYは、[最終行の後に](vdp_command.v#L782) 開始Yへ戻るため、DY0のまま。Y端で打ち切った場合も同じ。
- NYはNY0のまま。
- 1バイトは8ドット分なので、NXは8以下で使う。テストではNX=8を確認した。

LFMMは、NX文字を横に並べて描く。終了後にR#46だけを書き直せば、続きの文字を同じ行に描ける（NY0=0として1024行描くことはない）。
- DXは、作業用の [文字開始X](vdp_command.v#L657) で文字ごとに進め、[次の文字の先頭](vdp_command.v#L698) に使う。DXレジスタも [文字ごとに進める](vdp_command.v#L645) ため、終了時は DX = `DX0 + 8 × NX`（9bitで折り返す）。画面X端で文字の途中に終わった場合は、その文字の分を進めない。
- DYは、[各文字の最終行の後](vdp_command.v#L768) に開始Yへ戻る。最後の文字も同じなので、DY = DY0 のまま。Y端で打ち切った場合も同じ。
- NYは、各文字の最終行の後にNY0を読み込み直すため、NY0のまま。

LFMMの内部フォントアドレスは、[LFMMだけが進める](vdp_command.v#L454)。
- 通常完了時は `F0 + NX0 * H` になる（18bitで折り返す）。HはNY0、NY0=0の場合は2048行（128KBモードでは1024行）。
- DIY=1でY上端を越える場合も、描かなかったフォント行を飛ばして次の文字へ進む。
- R#32～R#34への書き込みはSX/SYとFを同時に変更する。ただし、進んだ後のFをSX/SYへ書き戻すことはない。

### 7. STOP

STOPは、途中まで更新したDY/SY等をそのまま残し、NYに残り行数を書き戻す。
Geo3DのHMMV最適化をSTOPで中断した場合は、元のLINEのNX/NYに戻す。
互換モード（V58=1）で追加コマンドを発行した場合も、STOPとして扱う。

## 共通の注意

- 「保持」は有効なビットについての記載。開始時に、SXのbit11～9（LRMM以外）とNXのbit10～9は0にする。SYの未使用上位ビットも、128KB／256KBモードに応じて0にする。
- HMMC/LMMC/LFMCのCLRには、実行中のCPU転送で最後に書いた値が残る。
- 実行中にCPUがNX/NYの各バイトを書いた場合、[書き込み済みマスク](vdp_command.v#L832) によって、そのバイトを終了時の書き戻しから保護する。
- Geo3Dの水平LINEを内部HMMVに置き換える [最適化](vdp_command.v#L345) は、新コマンドではない。DYを保持し、終了時にLINEのNX/NYと内部コマンド種別へ戻す。このため、表ではLINEに含めた。
- R#28～R#30のVRAMバンクは、コマンドでは変更しない。管理は [CPUインターフェース](vdp_cpu_interface.v#L746) が行う。

## 確認

- 監査用ModelSimベンチ（SCREEN5、128KB／256KBモード）で全16コマンドを確認した（計28ケース）。内容は、通常完了、DIY=1でのY端打ち切り、NY0=0、LMCMのDIY=0/1/端、POINT、STOPの待機中／実行中、LRMMのXHR=0/1、LFMC、LFMMの通常／上端クリップ、他コマンドでのFの保持。
- 既存の `test_vdp_command`（tb / tb_flushend）、`geo3d/test_hmmv` が通過する。
- 実機V9958基準の `test_vdpchk`（[gen_vdpchk.py](../../../../test/VDPCHK/gen_vdpchk.py) のモデル）で回帰を確認した。
- 終了時の状態を確認するテストを `VDPREG.COM`（テスト番号875～1484、610項目）にまとめた。R#32～R#46は読み戻せないため、コマンドの実行後に一部のレジスタだけを書き換えて次のコマンドを起動し、描画結果とS#7～S#9で前のコマンドが残した値を確認する。
  - 対象は SCREEN0～12、FG4=1（全13モード）、256KBモード。
  - 確認する項目：
    - 全V9958互換コマンドのDY・SY・NY・CLR。
    - 打ち切り時の `NY0 - N`。
    - 待機中のSTOP。
    - LFMMのDXの進み、DY/NYの保持、Fの進み。
    - LFMC（NX=8）のDXの進み、DY/NYの保持。
  - LRMM、LMMC/HMMC/LFMCのCLR（CPUが最後に書いた値になる）、実行中のSTOPは対象外。
  - RTLシミュレーションは `test_vdpchk` に `+script=vdpreg` を指定して実行し、全項目NGなし。実機ではSX-2（内蔵V9958無効化版）+ V9968カートリッジ（I/O 98h）でVDPREG・VDPCHKとも全項目パスした。FS-A1GT（V9958）でもVDPREG 0/244（V9968専用の362項目はスキップ）、VDPCHK 0/559（同315項目スキップ）で全項目パスした。
